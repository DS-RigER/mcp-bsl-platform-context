Global context.BeginGetFileFromServer

Global context

BeginGetFileFromServer

Available since version 8.3.15.

Syntax variant: With dialog

Syntax:

BeginGetFileFromServer(<Address>, <FileName>, <GettingFilesDialogParameters>)

Parameters:

<Address> (required)

Type: String.
Placing data in a temporary storage, or in the infobase.
The parameter cannot be an empty string. Otherwise, an error message is generated.

<FileName> (optional)

Type: String.
File name that will be offered to the user to save the file. User can change the file name.
Default value: Blank string.

<GettingFilesDialogParameters> (optional)

Type: GetFilesDialogParameters.
The structure containing dialog box parameters that will be shown to the user.

Description of method variant:

Starts receiving of a file and saves it to the local file system of the user prompting the user to select location of the received file.
File operation extension is not required in web client.
Depending on browser settings, in web client, you will be suggested to save the file with the specified name.
In thin and thick clients, a dialog box appears where you can specify what to do with the received file - whether to open it or save it to the selected directory. If the <FileName> parameter is not specified, file opening operation is unavailable. Upon opening the received file, it is checked for the application associated with the file type. The check is carried out by file extension. If an appropriate application is not found, the system dialog box for selecting an application to open the file is displayed. After you choose the application, the file opens in it. If you do not choose an application, file opening is canceled.
On the mobile platform, the dialog box for selecting a file is not displayed.

Syntax variant: Without a dialog

Syntax:

BeginGetFileFromServer(<NotifyDescriptionOnCompletion>, <Address>, <PathToFile>)

Parameters:

<NotifyDescriptionOnCompletion> (optional)

Type: CallbackDescription.
Contains the description of the procedure to be called after finishing with the following parameters:
  • <ReceivedFile> – an object of the TransferredFileDescription type.
  • <AdditionalParameters> – value that was specified when creating the CallbackDescription object.

<Address> (required)

Type: String.
Placing data in a temporary storage, or in the infobase.
The parameter cannot be an empty string. Otherwise, an error message is generated.

<PathToFile> (required)

Type: String.
Path to a file to save the file in.

Description of method variant:

Begins receiving a file and saves it to the user's local file system by the specified path. In this case, user cannot change the location of the received file.
File system extension is required in web client.

Description:

Begins receiving file.

Availability:

Thin client, web-client, mobile client, thick client, mobile application (client).

Available since:

Available since version 8.3.15.
