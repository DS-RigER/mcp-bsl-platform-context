Global context.AttachAddIn

Global context

AttachAddIn

Available since version 8.0.

Syntax variant: By identifier

Syntax:

AttachAddIn(<ObjectIdentificator>)

Parameters:

<ObjectIdentificator> (required)

Type: String.
Identifier of the external component object as a ProgID (Programmatic Identifier) of the MS Windows registry (for example, "AddIn.Scanner").
Must be consistent with information stored in the system Registry.

Description of method variant:

The component should be developed using the COM technology and entered in the MS Windows registry.
Such components are compatible with 1C:Enterprise 7.7 components.
Attention! The method variant does not operate at server and in the external connection.

Syntax variant: By name and location

Syntax:

AttachAddIn(<Location>, <Name>, <Type>, <AttachmentType>)

Parameters:

<Location> (required)

Type: String.
The location of the external component.
The following can be used as the location:
  • path to the external component file in the file system (unavailable on the web-client); not a ZIP archive;
  • full name of the template storing binary data or a ZIP archive;
  • URL of the external component stored as binary data or a ZIP archive in a format similar to GetURL.

<Name> (required)

Type: String.
A symbolic name of the attached external component.
The name must satisfy the 1C:Enterprise script naming conventions.

<Type> (optional)

Type: AddInType.
The type of the attached external component.
Is not used, if the component is ZIP-archived.

<AttachmentType> (optional)

Type: AddInConnectionType.
Add-in attachment type.

In Version8_3_20 or older configuration compatibility mode, the NotIsolated value is used.
In other cases, Isolated is used on the server, and NotIsolated on the client.

Description of method variant:

Attaches components developed using the Native API and COM technologies.
The component can be stored in an infobase or a configuration template as binary data or a ZIP archive.
For the thin client and web-client, the component has to be preliminarily installed using the InstallAddIn method.

Returned value:

Type: Boolean.
True - is attached successfully.

Description:

Attaches add-in objects to 1C:Enterprise.
External components can be stored as binary data or a ZIP archive in the infobase or configuration templates, or in a file system file.
For the thin client and web-client, the component has to be preliminarily installed.

Availability:

Thin client, web-client, mobile client, server, thick client, external connection, mobile application (client), mobile application (server), mobile standalone server.

Note:

External components can be developed using the Native API or COM technologies. The components developed using the COM technology are compatible with 1C:Enterprise 7.7 components.
The web-client can work only with archived components in the infobase.
The thin client can work with archived components in the infobase and components located in the file system.
The thick client can work with all variants of storing. At that, if a component is installed using the InstallAddIn method, this component is used, and if it is not installed, it is obtained when connecting.
The server can work with all components. The component is cashed for the server session.

Example:

If AttachAddIn("AddinObject.Scanner") Then
    Message("Component for the bar code scanner is loaded");
Else
    Message("Component for the bar code scanner is not loaded");
EndIf;
